# SwiftPuzzles
 
iOS-приложение: пазлы со схемами Swift-концепций на пастельном градиенте. Собрал пазл — получил короткую теорию с примером кода. Потом тема возвращается на повторение (режим «недостающий кусок», интервалы по Лейтнеру).
 
Полный план MVP: `docs/MVP.md`. Перед работой над новым этапом сверяйся с ним.
 
## Стек
- SwiftUI, SwiftData, iOS 18.6+
- Без сторонних зависимостей, пока явно не договоримся
- Контент (темы, теория, картинки) — JSON + ассеты в бандле; в SwiftData только прогресс и настройки
## Сборка и тесты
Одна схема `SwiftPuzzles`, линтера и SPM-зависимостей нет — всё через `xcodebuild`:
```bash
# сборка
xcodebuild -project SwiftPuzzles.xcodeproj -scheme SwiftPuzzles \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' build
# все unit-тесты
xcodebuild -project SwiftPuzzles.xcodeproj -scheme SwiftPuzzles \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' test -only-testing:SwiftPuzzlesTests
# один тест (Swift Testing: Target/Suite/func())
xcodebuild -project SwiftPuzzles.xcodeproj -scheme SwiftPuzzles \
  -destination 'platform=iOS Simulator,name=iPhone 18 Pro' test \
  '-only-testing:SwiftPuzzlesTests/ContentTests/bundledContentIsValid()'
```
## Настройки проекта, которые легко упустить
- Папки синхронизированы с Xcode (`PBXFileSystemSynchronizedRootGroup`): новый файл внутри `SwiftPuzzles/` попадает в таргет сам. `project.pbxproj` руками не править.
- В таргете приложения `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` + Approachable Concurrency: весь код по умолчанию на главном акторе, `nonisolated async`-функции выполняются на акторе вызывающего. Чтобы реально уйти с main (например, тяжёлая нарезка картинки) — нужен `@concurrent`.
- Swift language mode 5 (`SWIFT_VERSION = 5.0`).
- Deployment target — iOS 18.6 у всех таргетов: API новее — только через `if #available`. Обратную совместимость с iOS 17 не тащим (аудитория — разработчики на свежих iOS).
- Unit-тесты — Swift Testing (`@Test`, `#expect`), UI-тесты — XCTest.
## Ключевые решения (не менять без обсуждения)
- Куски пазла прямоугольные, без «ушек»
- Сложность (размер сетки) выбирает пользователь; картинка режется на куски в коде под выбранную сетку
- «Битые» куски для повторения не рисуются заранее: хранится целая «битая» версия схемы + нормализованная область ошибки, кусок вырезается под текущую сетку
- Интервалы повторения: 1, 3, 7, 14, 30 дней; ошибка → stage = 0
## Как мы работаем: осознанный вайбкодинг
Код пишешь ты, но я должен понимать всё, что попадает в проект.
 
**Рутина — делегирую полностью.** Пиши сам, без лишних объяснений:
вёрстка простых экранов, экран настроек, загрузка JSON, ассеты, иконки, boilerplate, превью.
 
**Учебно важные части — работаем осознанно:**
- нарезка картинки на куски и геометрия сетки
- drag & drop, жесты, snapping
- анимации и хаптики
- SwiftData-модели и запросы
- логика повторений (Лейтнер)
- архитектура и разделение ответственности (модели / вью / логика)
Для этих частей:
1. Перед кодом — коротко объясни план: что будешь делать, какие файлы затронешь, какие концепции Swift тут ключевые.
2. После кода — 3–6 строк о неочевидных местах: почему так, а не иначе.
3. Если я пишу «не понял» про концепцию — не разворачивай длинное объяснение здесь. Назови концепцию одной строкой и остановись: я разберу её отдельно и вернусь.

## Git
Git я учу как инструмент, поэтому:
- **Не коммить сам.** Когда доходим до смысловой вехи — сам предложи коммит:
  - какие файлы должны войти, а какие нет;
  - на что посмотреть в `git status` / `git diff --staged` перед коммитом;
  - готовые команды целиком;
  - сообщение в формате Conventional Commits на английском (`feat:`, `fix:`, `refactor:`, `chore:`, `docs:`).
- Коммиты по смыслу, а не по объёму: одна веха — один коммит.
- Перед опасными операциями (`reset --hard`, `push --force`, rebase, удаление веток) — предупреди и объясни последствия.
- `.gitignore` для Swift/Xcode (включая `.DS_Store`, `xcuserdata/`, `DerivedData/`) — до первого коммита.
