# SwiftPuzzles — план MVP
 
## Суть
Пазл со схемой Swift-концепции на пастельном градиенте. Человек собирает пазл и в награду получает короткую теорию по этой же схеме с маленьким примером кода. Потом тема возвращается на повторение в виде пазла с недостающим куском.
 
**Цель MVP:** проверить, что цикл «собрал → прочитал → через пару дней вспомнил» работает и не надоедает. Плюс получить аккуратный портфолио-проект на SwiftUI.
 
---
 
## Что входит в MVP
 
### 1. Контент: 10 тем в 3 альбомах
По одной теме на пазл. Темы сгруппированы в альбомы (как направления в Cezelle), у каждого альбома прогресс «N из M». Примерный список:
 
**Основы**
1. Optionals и `if let` / `guard let`
2. `enum` с associated values + `switch`
3. Error handling (`throws` / `try` / `do-catch`)
4. Протоколы и protocol extensions
5. Generics
**Память и типы**
6. Value vs Reference types (struct / class)
7. Closures и захват значений
8. ARC, `weak` / `unowned`
 
**Concurrency**
9. `async` / `await` и Task
10. Actors и data races
 
На каждую тему нужно:
- **Схема** (картинка 3×4, на градиенте)
- **Теория:** 4–8 предложений
- **Пример кода:** 5–15 строк
- **2 «битые» версии схемы** для режима повторения: та же картинка целиком, но с одной ошибкой (стрелка не туда, не тот модификатор и т.п.) + координаты области ошибки
> Почему целые картинки, а не отдельные куски: сетка разная, поэтому кусок нельзя нарисовать заранее. В режиме повторения код находит ячейку текущей сетки, в которую попадает область ошибки, и вырезает этот кусок из правильной и из «битых» картинок.
 
> Контент — узкое место. Схемы лучше делать руками в Figma/Keynote или собирать программно, а не генерировать. Теорию можно брать из Свифтёнка, но вычитывать.
 
### 2. Сборка пазла
- **Сложность выбирает пользователь:** например, 3×4 / 4×5 / 5×6 (по умолчанию 3×4)
- Куски прямоугольные, **без «ушек»** (это решено окончательно)
- **Механика как в Cezelle:** все куски сразу лежат на поле в перемешанном виде, отдельного лотка нет. Тащишь кусок на другую ячейку — они меняются местами
- **Склейка:** между кусками, которые не подходят друг другу, видна тёмная линия. Если два соседа стоят друг относительно друга правильно, линия исчезает и они склеиваются в группу
- Группа двигается целиком и больше не разъединяется. Куски, которые стояли на месте, куда переехала группа, перемещаются в освободившиеся ячейки
- Лёгкий хаптик, когда кусок встаёт на своё место; анимация в конце сборки
- Во время сборки теория недоступна: она — награда и открывается только после сборки
- Картинка режется на куски в коде под выбранную сетку, а не заранее
### 3. Награда: экран теории
- Схема целиком, теория, пример кода с подсветкой синтаксиса
- Блок «Подробнее»: ссылка на официальную документацию (глава The Swift Programming Language или страница developer.apple.com), открывается в браузере
- Кнопка «Понятно» → тема получает `stage = 1`, `nextReview = завтра`
### 4. Повторение: «недостающий кусок»
- Открывается уже собранный пазл, одной ячейки нет
- Внизу 3 варианта: правильный и 2 «битых»
- Верно → `stage += 1`; ошибка → `stage = 0`, повтор завтра
- После ответа короткое пояснение, почему остальные варианты неверные
### 5. Интервальное повторение (Лейтнер)
- Интервалы: **1, 3, 7, 14, 30** дней
- На главном экране плашка «На повторение: N»
- `stage` выше последнего → тема «освоена»
### 6. Мета-пазл (единственная награда-бонус в MVP)
- Большая картинка «Карта Swift» из 10 кусков
- Каждая освоенная тема открывает свой кусок карты
- Можно сделать отдельной вкладкой или показать прогрессом на главном экране

## Визуальный стиль
- Системная светлая и тёмная тема, без собственного фона
- У каждого альбома свой градиент (два hex-цвета в `content.json`): им залита карточка альбома на главном экране
- Один акцентный цвет для кнопок (варианты: оранжевый, синий, фиолетовый), с вариантами для светлой и тёмной темы в Assets
- Навигация — нативный TabView: «Главная» и «Настройки»
---
 
## Данные (SwiftData)
 
**Album**
- `id`
- `title`
- `gradient`: `{ from, to }` в формате `#RRGGBB`
- `topicIDs: [String]`: темы альбома в порядке показа
**Topic**
- `id`
- `title`
- `imageName`: схема
- `theory: String`
- `codeSample: String`
- `docsURL: URL`: ссылка на официальную документацию по теме
- `wrongImageNames: [String]`: «битые» версии схемы
- `errorRegion`: нормализованный прямоугольник (0…1) с областью, где спрятана ошибка; по нему вычисляется, какой кусок убрать в текущей сетке
> В `content.json` альбомы и темы лежат двумя плоскими массивами. Полей `order` нет: порядок альбомов — порядок в массиве `albums`, порядок тем — порядок `topicIDs`. Каждая тема входит ровно в один альбом; это, уникальность id и наличие картинок проверяются при запуске и в тестах.
**Settings**
- `gridSize`: выбранная сложность (cols × rows)
**TopicProgress**
- `topicID`
- `isSolved: Bool`
- `stage: Int`
- `nextReview: Date?`
- `lastReviewed: Date?`
> Контент (Topic) удобнее хранить в бандле как JSON + картинки, а в SwiftData держать только прогресс. Тогда контент можно обновлять без миграций.

## Экраны
1. **Главный:** карточки альбомов с градиентом и прогрессом; плашка повторений, прогресс мета-пазла
2. **Альбом:** сетка тем в 2 колонки, в плитке схема темы. Состояния: закрыта — серая, размытая, замок перед названием; следующая — серая, размытая, иконка Play поверх; начата — цветная, размытая; решена — цветная, чёткая
3. **Сборка пазла**
4. **Теория**
5. **Повторение:** недостающий кусок
6. **Карта Swift:** мета-пазл
7. **Настройки** (вкладка): выбор сложности

## Этапы
 
| # | Этап | Результат |
|---|------|-----------|
| 1 | Модели + JSON с мок-контентом (см. ниже) | Данные грузятся, альбомы и темы на экране |
| 2 | Нарезка картинки под любую сетку + выбор сложности | Куски отображаются в перемешанном виде |
| 3a | Перетаскивание и обмен одиночных кусков + линии между неподходящими соседями + проверка сборки | Пазл собирается (пока без склейки) |
| 3b | Склейка в группы + перемещение группы целиком | Механика как в Cezelle |
| 4 | Экран теории + подсветка кода | Полный цикл «собрал → прочитал» |
| 5 | SwiftData-прогресс + логика Лейтнера | Темы уходят на повторение по датам |
| 6 | Режим «недостающий кусок» | Работает повторение |
| 7 | Мета-пазл | Видна общая картина прогресса |
| 8 | Контент: все 10 тем | Приложение можно дать людям |
| 9 | Полировка: хаптики, анимации, иконка, тёмная тема | Готово для портфолио / TestFlight |
 
### Мок-контент для этапов 1–7
Реальные схемы и тексты делаются только на этапе 8, до этого всё на заглушках:
- **Одна тестовая картинка** на все темы: градиент в финальной пропорции (3:4) + крупная сетка с номерами ячеек или простая фигура, чтобы глазами видеть, правильно ли собран пазл и стоят ли куски на местах
- **Одна «битая» версия** этой картинки: та же, но с заметной меткой (например, красный крестик) в одной области + её `errorRegion`, чтобы проверить режим повторения
- **Тексты-заглушки реальной длины:** «Текст теории для Concurrency…» на 4–8 предложений и код на 5–15 строк, чтобы экран теории сразу верстался под настоящий объём
- 3 альбома, в каждом по 1–2 темы
---
 
## Не входит в MVP
- Повороты кусков
- Редкие «золотые» пазлы
- Стрики, уведомления
- Аккаунты, синхронизация, бэкенд
- Генерация контента в приложении
## Открытые вопросы
- Как делать схемы: вручную или программно из SwiftUI-шейпов?
- Альбомы открываются по порядку или все сразу? (Темы внутри альбома — по порядку: следующая открывается, когда решена предыдущая.)
- Пример кода нужно уметь копировать или запускать?
- Как тестировать: на себе и паре знакомых, или сразу выкладывать в TestFlight?
